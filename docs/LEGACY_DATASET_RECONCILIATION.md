核验日期：2026-09-18  
核验范围：

- `data/raw/脸谱/整理工作/爬虫脸谱图集.zip`

## 2026-09-20 项目负责人确认

项目负责人已确认：`data/raw/脸谱新一步/272数据张丹阳.xls` 中的 `序号` 与 `data/raw/脸谱/整理工作/爬虫脸谱图集.zip` 中图片文件名编号是一一对应关系，即 `001 -> 序号 1`，一直到 `272 -> 序号 272`。

因此，在后续 `2026 Reconstruction` 的现代数据集构建中，该关系记录为 `user_confirmed_sequence_mapping`，可以作为当前项目数据集的有效图片-元数据对应关系使用。

同时，项目负责人确认现代数据集阶段不再处理“论文标签体系与当前标签无法对应”的问题；标签分类按当前 XLS 中实际 `谱式` 文本进行统计、筛选和划分。该说明不修改 raw 文件，也不把论文未说明的标签映射补写为 2019 Original。

## 核验结论

当前可以确认：

- 压缩包有 272 个图片成员，272 张图片全部可以读取。
- XLS 有 272 条数据记录，`序号` 是完整的 1-272。
- XLS 的 39 个有名称字段可以被完整提取。
- XLS 中有 20 个非空 `谱式` 文本值，另有 16 条 `谱式` 缺失。
- 论文点名的 6 个类别在 XLS 中都出现，但其中 `十字门脸` 只有 15 条、`整脸` 只有 17 条。
- 经项目负责人确认，图片 ZIP 的数字后缀和 XLS 的 `序号` 是 001-272 的一一对应关系。

当前不能确认：

- 该一一对应关系不是论文正文自身给出的逐文件清单，而是项目负责人对当前历史资产的确认。
- 这 272 张 ZIP 图片就是论文中用于 2019 MLP 的最终图片。
- 这份 XLS 就是论文中 MLP 的最终训练输入。
- 当前资产具备论文所说的完整 16 类标签体系、4:1/80:20 划分或 10-fold fold 分配。

因此当前状态是：

> `272_candidate` 已完成真实性和结构盘点，并可作为 `user_confirmed_sequence_mapping` 的现代数据集输入；是否升级为可训练的 2019 `legacy_dataset` 仍取决于 KNIME workflow、原始划分和实验结果等证据。

### B.3 当前图片和 XLS 的可验证对比

图片尺寸与 XLS 图像属性不一致：

- ZIP 图片主要是约 83-123 x 110-152 的小图。
- XLS 记录的图像属性主要是约 287-425 x 350-515。
- 按 `001` 到 `272` 的候选序号逐条比较，272 条均不是宽高完全相同。

但是，像素宽高不一致并不等于图像内容一定不同。按同一序号比较图片宽高比：

- 269/272 条的宽高比差值不超过 `0.005`。
- 270/272 条的宽高比差值不超过 `0.01`。

这与 ZIP 图片是另一份同源图片的缩略版或降采样版相容，是支持序号关系的结构证据。2026-09-20 经项目负责人确认后，该编号关系在现代数据集构建中升级为 `user_confirmed_sequence_mapping`；宽高不一致仍说明 ZIP 像素尺寸与 XLS 图像属性不是同一组文件属性。

另外，ZIP 中的图片与以下已展开目录中的同编号图片进行 SHA-256 比较：

`data/raw/脸谱新一步/网络图片汇总/`

结果是：

- 265/272 个编号在该目录中有同编号、同 SHA-256 的图片。
- 7 个编号在该目录中没有对应展开文件：`059`、`199`、`200`、`201`、`202`、`203`、`204`。

这说明 ZIP 与另一份网络图片资产存在强关联。单靠 SHA-256 对比不能证明 ZIP 图片与 `272数据张丹阳.xls` 的角色、剧目和谱式字段对应；当前项目采用的对应关系来自项目负责人对编号一一对应的确认。

## C. 两者可以对应

### C.1 数量和序号层面

- 论文描述 272 张带标签图片。
- 当前 ZIP 有 272 张图片。
- 当前 XLS 有 272 条记录。

`data/processed/272_candidate/image_metadata_mapping.csv`

- ZIP 内 272 张图片均能读取。
- 每张图片都有 SHA-256。

## 对 `legacy_dataset` 的建议构建方式

现代数据集已可基于项目负责人确认的序号映射建立。若后续要建立 2019 `legacy_dataset`，仍建议保留分层结构：

```text
legacy_dataset/
  image_manifest.csv
  metadata_raw.csv
  image_metadata_mapping.csv
  label_inventory.csv
  split_manifest.csv
  provenance.md
```

建议约束：

1. `image_manifest.csv` 和 `metadata_raw.csv` 作为两个独立实体表保留。
2. 当前项目数据集可使用项目负责人确认的 `user_confirmed_sequence_mapping`。
3. `label_inventory.csv` 按当前 XLS 原始 `谱式` 文本统计和筛选；现代数据集阶段忽略论文标签体系与当前标签的对应问题。
4. 如果未来复现 2019 Original MLP，再单独处理论文 16 类、六类描述和 KNIME 输出范围，不反向污染现代数据集。
5. 未恢复的 train/test split 保持 `unknown`，不按 4:1 或 80:20 自行生成 2019 split。
6. 在以下条件满足前，不启动“2019 Original reproduction”训练：
   - 272 条记录的最终版本和来源得到确认；
   - 训练/测试边界和 10-fold 解释得到确认，或明确命名为 2026 approximation；
   - KNIME/MLP 参数缺口被单独记录。

下一步最有价值的资料工作是寻找原始图片高分辨率版本、KNIME workflow、训练/测试清单和实验输出。在这些资料出现之前，当前 272 数据可以用于 `2026 Reconstruction` 的现代视觉数据集准备；是否能称为已重建的 2019 MLP 数据集仍需单独证据。
