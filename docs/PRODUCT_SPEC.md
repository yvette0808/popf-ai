# POPF 产品规范

状态：`2019 Original reference + 2026 Reconstruction scope`

本文件区分论文中描述的 2019 网站功能和未来 2026 产品工程。当前不开发前端，不声称原网站仍然可访问或已经被恢复。

## 1. 2019 Original 网站功能

论文称网站有两个主要功能：

1. 连接图片数据库，动态展示图片和关联信息。
2. 提供上传入口，调用识别模型给用户反馈。[PAPER:P4]

论文描述的页面包括：

### 1.1 Welcome

- 使用脸谱图片引导用户进入学习环境。
- 提供关于京剧脸谱的基础介绍。

### 1.2 Modules

- 展示 16 个类型图标。
- 点击图标后查看该类型的代表性图片。
- 展示角色介绍、剧目和剧情、颜色及其含义、脸谱结构等相关信息。
- 论文举例提到点击 eunuch face 可看到 Liu Jin 和 Jia Gui 的脸谱。[PAPER:P5]

### 1.3 Upload port

- 页面有一个大号“+”作为图片上传入口。
- 模型比较上传脸谱与各类型特征的相似/归属概率。
- 页面返回最高概率类型。
- 结果后出现 `yes` 和 `no` 图标，用户可对识别结果进行反馈。
- 论文用 Kong Xuan 的脸谱和 goblin face 作为示例。[PAPER:P5]

### 1.4 About us

- 论文将 about us 列为网站组成部分。
- 页面具体字段、文案和交互未说明。

### 1.5 用户和价值

论文把网站描述为：

- 对脸谱文化感兴趣者的知识仓库。
- 设计师的素材仓库。
- 脸谱传承者的交流平台。[PAPER:P4-P5]

论文还描述了经典视觉风格和滚动式整体框架，但没有提供可复用的完整前端源代码、部署地址、接口协议或设计稿。

## 2. 数据库和页面内容边界

2019 论文明确说使用 MySQL 保存图片和关联信息，但没有 schema。页面内容也不能直接推断数据库表结构。

当前可以作为内容候选的字段只有：

- 角色。
- 剧目。
- 脸谱类型。
- 介绍。
- 角色介绍。
- 剧情。
- 颜色及其含义。
- 脸谱结构。

这些字段是否全部存在、如何关联、哪些来自人工编辑，均为 `Unknown`。

## 3. 2026 Reconstruction 产品范围

最终重建计划包含：

1. 数据集可追溯展示。
2. 2019 MLP 基线识别。
3. 现代 CNN 模型识别。
4. 上传图片推理。
5. 识别结果与已验证脸谱知识关联。
6. 用户对预测结果的反馈。
7. Bad Case 审核与分析。

其中：

- 图片识别和类别信息承接 2019 Original 的目标。
- 现代 CNN、版本化推理接口、知识关系层、反馈记录和 Bad Case 报表属于 2026 Reconstruction 的工程化扩展，除非后续找到原始资料，否则不能写成 2019 已有功能。

## 4. 2026 产品安全和可信约束

### 4.1 知识内容

- 每条文化知识必须保存来源、来源日期、审核状态和编辑记录。
- 不能把模型预测类别当成角色身份、剧情或文化含义的事实。
- 对未核实内容显示待补证状态，不发布猜测。

### 4.2 识别结果

- 显示模型版本和处理版本。
- 至少保留 top-k 概率，而不是只保存一个不可解释的类别。
- 对不在已支持类别范围内的输入保留“不确定/待审核”状态。
- 不把论文“约 70%”直接显示为当前系统准确率。

### 4.3 用户反馈

2019 论文明确描述了 `yes` / `no` 反馈入口。2026 需要进一步定义：

- 反馈是否匿名。
- 是否保存上传原图，保存多久。
- 用户是否可以提供纠正类别。
- 哪些反馈需要人工复核。
- 反馈如何进入训练数据候选集。

这些问题论文未说明，当前不做默认决定。

### 4.4 Bad Case

系统化 Bad Case 分析是 2026 目标能力。至少应能关联：

- 输入图片或其安全标识。
- 模型版本和预测概率。
- 用户反馈。
- 人工复核标签。
- 错误原因类别。
- 是否进入后续数据修订或再训练候选集。

当前没有任何 Bad Case 数据，不能生成示例结果或错误率。

## 5. 前端边界

当前阶段禁止开始前端开发。前端实现必须等以下内容明确后再开始：

- 数据和类别 schema。
- 推理 API 契约。
- 知识内容来源和审核流程。
- 反馈数据处理和隐私规则。
- 2019 页面复原范围与 2026 新增功能的视觉边界。
